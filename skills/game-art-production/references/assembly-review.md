# 组合与状态验收

## 场景先有坐标，再有动效

确定统一画布、相机、地标和图层前后关系。每张变体至少对照屋脊、门脚、栈桥角等三个锚点；不能只比宽高。昼夜变体允许照明变化，建筑结构和物件位置不得暗改。微小生成偏差先显式记录；不称为可无缝替换的引擎资源。

角色的图像边界不是脚底。分别记录可见内容框、接触点、地图尺度和对话尺度。动作姿势与原角色核对脸、发型、服装、工具和身体比例。若复用对话视角制作地图动作，说明它是叙事插演；正式地图角色仍需对应镜头的转面或动画资源。

## 效果必须说明原因

| 事件 | 可见反馈 | 组合检查 |
|---|---|---|
| 木料交付 | 库存变化、修缮姿势、敲击时扬尘、修复状态 | 手与木板接触；尘不盖住脸和门窗；完成后消失 |
| 点亮灯房 | 灯具消耗、窗与灯光变化、环境切换 | 灯的位置一致；发光不能变成新的灯体；文字仍读得清 |
| 船到码头 | 进场路径、水纹/尾迹、靠泊、奖励 | 船不能穿过陆地；水纹在船下；奖励只发一次 |
| 合成与解锁 | 物品升级、短促放大、锁区变化 | 反馈不抢点击；等级剪影不被遮；重复操作不重复扣费 |

将事件、时长、完成条件、可跳过/减少动态模式和中断行为写入任务。状态变化用同一纯函数验证；浏览器、视频和截图共用场景配方。演示可压缩时间，但要说明是演示时间，不能虚构实际功能。

## 检查的顺序

单件透明/尺寸 → 实际小尺寸 → 深浅背景 → 场景接触与层级 → 转场中间帧 → 完整交互路径 → 换目录交付复核。保留具体问题与修正，而不是只写“统一、精致、通过”。记录屏幕尺寸和工具；未做的 Mac、真机、引擎或真人交接不标通过。
