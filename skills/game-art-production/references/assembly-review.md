# 组合与动作验收

For expanded asset sets, use [asset richness and sustained playback](asset-richness-and-playback.md) to connect family/state/direction coverage, actual UI and fonts, honest asset counts, 1× play and performance observations, and resumable production receipts. Apply it alongside the contact, timing and assembly checks below.

## 场景先有坐标，再有动效

确定画布、相机、地标和图层关系，用项目实际可见的锚点对齐变体，不能只比宽高。昼夜或天气可以改变照明，建筑、路径与交互位置要按规则保留。记录偏差及影响；不把尚有漂移的变体称为可无缝替换的引擎资源。

图像边界不是脚底。记录可见内容框、接触点、地图尺度与对话尺度，按用途使用正确视角。动作与原角色核对脸、发型、服装、工具和比例。对话立绘插入地图只证明叙事插演；地图动画仍需对应镜头的资源。

组合时同时看轮廓、边缘、材质、光照、尺度、对比和文字层级。来自不同成员或 Agent 的文件即使使用同一色板，也可能不属于同一游戏。字体、图标和控件要用真实文案与状态放回画面，不能在另一张空白板上单独判定成立。

## 先决定动作，再选择制作方式

任务说明触发事件、角色意图、预备—作用—恢复、接触或附着点、总时长与结束状态。为有性格的短动作，可采用 6–20 张不同姿势或形变的画面作为制作方案；帧数由实际节奏决定，不约束所有粒子和 UI 反馈。其他可行方案是实际绑定的骨骼、逐帧绘制或可用工具生成的动画。不要为满足数字复制同一帧，也不要把整张立绘上下位移当成人物动作完成。

先播放首件，检查姿势差异是否真的表现重量、意图与节奏，再扩展动作家族。生成工具的输出必须逐帧检查身份、肢体数量、道具和背景稳定性；视频转出 20 个截图不自动成为可交付的精灵帧。需要独立帧时还要统一裁切、锚点、透明边和时序。

生成图上的名义网格不保证轮廓都在格内。先观察透明间隙和越界部件，再记录实际裁切框；微弱 alpha 像素与完全透明区域内的 RGB 不应直接决定可见边界。用浅深底合成检查，避免误删真实细节或无谓重画。全组保持同一缩放倍率，以根点、支撑脚或接触目标配准，不能逐帧按包围盒填满画布。实际播放待机—行走—停止，核对可见身高与脚底位置；走路还要辨认两腿交替，帧数足够并不证明步态成立。

帧曝光、接触事件和效果消费同一份时间表。例如落锤帧触发木屑，材料提交、修缮完成与奖励到账是不同事件；明确它们何时发生，不能提前显示完成物。跳过动作、减少动态、刷新与快速重复点击仍应只完成一次资源变更。记录实际接触帧和状态变化，避免演示影片与可玩版本各自凭计时猜测。

沿路径移动时，步幅、移动速度和动作时钟也要相符；减速和暂停应同时影响位移与相应帧序。重开后旧动作的回调不能继续修改新一局的场景或奖励。

## 在画面和状态中验收

| 要验证的关系 | 实际观察 |
|---|---|
| 落脚与接触 | 固定支撑脚不滑；发力、敲击、抓握与目标位置和发生时刻一致 |
| 身份与附着 | 脸、轮廓、身体结构不漂移；手持物、装备与连接点随身体正确变化 |
| 起止与循环 | 首尾能接回对应待机；循环不跳帧；非循环动作不会意外重播 |
| 节奏与效果 | 预备、作用和恢复有层次；命中、扬尘或水纹跟随实际事件，不遮掉玩家判断 |
| 状态响应 | 触发、完成、中断、重复点击和减少动态模式有明确结果；视觉完成与资源/奖励变化对应 |
| 合成前后 | 来源物品和目标等级可辨，按既定家族升级；闪光与缩放不掩盖结构或身份错误 |

这些是按动作选取的观察维度。保留实际文件、播放速度、关键帧或时间点、看到的问题与修正。没有播放就只报告关键姿势检查；没有引擎、设备或原生编辑器就保留对应验收为待完成。

浏览器、宣传视频和截图尽可能消费同一资产与场景配方，宣传可压缩时间但须标明演示。运行中的事件、结束条件、跳过和中断必须真实执行，不能只写在字幕上。

## 检查的顺序

先看单件技术条件与实际尺寸，再看场景中的接触和层级，然后正常速度播放并查看关键中间帧，最后执行完整交互与换目录交接。只保留影响结果的观察；一串“统一、精致、通过”不能作为证据。
