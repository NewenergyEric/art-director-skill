# 团队视觉生产需求覆盖审计

> 这是 v0.4.1 的历史审计。主美建体系、家族/样板/渠道编译与自包含团队包的 v0.5 更新见[当前实现与验证](director-workflow-v0.5.md)。

审计日期：2026-10-09。依据是当前母 skill、运行脚本、批次协议和测试代码；这份报告不把功能说明、网页演示或测试夹具当作实际生产交付。

**总判断：已覆盖需求的工作流主干，并有可执行的任务、版本和批次工具；目前仍未达到端到端正式资产生产验收。** 它已经能减少“每位成员从头编一套提示词”的空间，但不能据此声称已消除角色变脸、风格漂移或团队品质差异。

本轮已用独立原创米拉与电商案例执行 [24 次 CLI 调用、17 条断言](../evals/public-demo/summary.json)，全部得到预期结果；核查任务路由、衣装与身份分离、组合约束和新版启用，不包含新图、PSD、正式批准或真人团队品质实验。检查方法见[执行说明](../evals/public-demo/README.md)。

适用对象是一起制作视觉元素及最终组合的团队，包括游戏、品牌 UI、电商促销和宣传海报。主美或设计总监提供已有材料、定义保持与变化的边界、判断更好的方向是否能在周期内落地；Agent 负责组织资料、调用规则、准备制作和交付。成员主要描述本次变化。

## 怎样理解“保底”

当前能提供的是共同输入、明确变量、同一判断、文件与版本追溯，以及对未检查事项的显式暴露。判断图像是否保持同一人物、是否属于同一风格，需要可读图的评审；判断资产能否落地，还需要编辑与目标场景中的检查。

同一图片被登记为多个参考用途时，运行层会提供来源和 SHA256；实际调用模型前按哈希合并图片附件、说明各用途，仍由 Agent 执行。文字规范不是图像参考，文件路径也不等于图像模型已经收到附件。缺素材时可继续做标明缺口的候选规划，不能凭此进入正式交付。

本地规范更新的准确行为是：

```text
主美调整工作草稿
  → Agent 构建、核验并按实际决定发布
  → current 指向新版本
  → 新任务读取新版；既有任务继续原版
  → 需要迁移的任务另行建立，并检查兼容性
```

主美已有的明确授权继续有效；日常制作不需要为每一张图重新审批。只有共享规则、采用范围或预算发生实质变化时，才需要依据已有授权处理对应决策。

## 三项最重要的剩余工作

1. **完成一条真实的正式资产交付。** 用可公开、可生产的输入，分别完成角色换装和促销组合：真实模型调用与参考、单件文件、PS/Figma 可编辑源、实际尺寸、最终组合、负责人验收。逐段保存产物与证据，才能把“交接准备完成”推进到“交付完成”。
2. **验证非工程人员能够独立使用。** 让主美用已有资料接入项目，让成员直接说变化、继续旧任务和使用新规范；观察 Agent 是否正确执行，不让用户补写 JSON。按实际需要补齐类别薄入口、所用图像模型与编辑器的操作适配；若需要多人在线工作台，再实现真实服务与同步，不能用 HTML 原型代替。
3. **用连续真实批次验证品质差异是否下降。** 同一任务与材料下比较自由描述和 skill 流程，分别记录身份/品牌错误、风格错误、首次通过率、返工轮次和总用时；保留分母、unknown、模型条件与评审依据。脚本测试只能证明程序行为，不能替代团队效果实验。
