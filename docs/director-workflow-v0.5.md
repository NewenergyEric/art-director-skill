# v0.5 · 从主美的专业判断到团队生产流水线

本轮完成日期：2026-10-10。保留已有规则、成员任务、创意探索、版本和批次工具，在其上补齐主美建立体系与团队接包的完整路径。

**产品目标：帮助主美把专业判断建立成可执行的制作体系，让团队在同一标准下持续交付，并把更好的结果纳入下一版。** 一致性、质量和效率由共同输入、样板校准、明确分工、逐项检查、定向返工和版本管理共同支持。

## 两类用户如何工作

| 主美 / 设计总监 | 团队成员 / 外包 |
|---|---|
| 提供已有作品、参考、批注和项目目标；资料不完整也能开始 | 接收项目包，安装到所用 Agent 或让它读取包内入口 |
| Agent 先整理具体可评审的定位与规则初稿，再补关键缺口 | 用自然语言说明要做的类别、组件或状态，由 Agent 绑定家族与版本 |
| 逐步建立整体语言、类别要求、组件家族、允许变化和渠道约束 | 按同一规范准备和执行生成、编辑、组合与导出任务 |
| 选择能解决分歧的样板和首件，明确验收与真实决定 | 单件、源文件、组合证据一起交付，缺项和未检查项可见 |
| 把规则、样板、参考、手册、工具和入口直接打包交接 | 收到具体返工项，保持其他已满足要求的部分；沿固定版本继续 |
| 结合实际效果、成本和周期决定采用新探索、更新基线 | 新任务采用已启用版本；既有任务和批次保留快照 |

当前公开入口已收拢为[统一上手介绍](landing.zh.html)，展示完整功能片和主美、成员的对话开场白。早期工作台与调用图地址跳转到该介绍；下文保留 v0.5 实现记录，实际操作在 Agent 中完成。

## 本轮增加了可执行能力

1. **专业建项引导。** [主美指南](../references/director-workflow.md)要求 Agent 从已有材料先写填实初稿，给出具体判断、依据、取舍和下一步样板；不用让设计师先学工程术语或填完整问卷。支持角色、场景、物品链、UI 状态、商品、活动海报、社媒模板和多渠道组合。
2. **家族与样板进入规范源。** `direction` 记录定位、组件/资产家族、样板职责和交付渠道。家族有固定项、变量、规则、参考及技术要求；代表样板按项目风险选取，不固定张数。已批准状态需要真实文件与决定依据，参考阅读尺寸不推定为交付尺寸。
3. **五份手册同源生成。** 资料索引、项目定位、设计规范、交付与验收、参考与反例由同一个 `style-pack.json` 派生。主美可以自然语言批注，Agent 回写源并重建，避免团队维护多份不同版本的规范。
4. **项目包带着工具交给成员。** 新包内含 `SKILL.md`、五份手册、规范、所需参考，以及规则、成员运行、批次检查三个脚本。成员解压到新位置即可让 Agent 初始化工作区、建立和恢复任务、检查交付，不依赖原主美电脑的源码目录。
5. **规范真正进入任务和收件。** `--family`、请求的 `family` 及组合组件的家族绑定会编入对应规则、参考和检查。漏绑、跨类别错绑或交付家族不符会被发现；家族、样板与渠道要求自动进入质检，不能用一句通用“通过”代替逐项检查。

旧包和旧请求继续可用。已有换装、身份保持、创意预算、版本冻结和批次能力保留；换装作为体系建立后的一个使用例。

## 实际验证

- [核心回归](../evals/director-workflow-v0.5/core-tests.json)：108 项，106 通过，2 项因 Windows 符号链接权限跳过；无失败。
- [真实运行](../evals/director-workflow-v0.5/execution-summary.json)：构建并归档 2 套包、生成 10 份手册、解压到新位置后只用包内工具建立 6 个成员任务；30 条断言通过。共记录 29 次调用，包含 1 次示例请求缺少空主体字段的初始错误，修正后重试成功，原记录保留。
- 真实验证覆盖：家族和组件绑定、样板与渠道检查带入、待建立的必需样板阻止正式发布、未交资产的批次不能记为完成、旧包兼容和接包后的独立使用。
- [页面检查](../evals/director-workflow-v0.5/demo-check.json)：静态路径与 Node 交互检查，保留当前文件哈希；不是浏览器视觉验收。
- [独立 Agent 试用](../evals/director-workflow-v0.5/forward/DIRECTOR-REVIEW.md)：未参与实现的 Agent 只读母 Skill 和一张原创方向图，从“四人团队、主美不知道如何开始”出发，写出具体专业初稿、8 个家族、22 条候选规则和 5 项样板计划，生成独立项目包并准备 6 个任务；10 项语义核对通过。主美决策与未定技术条件保持待确认。
- 试用发现并补齐了组合交接规则：子资产状态、等级和姿态各自开任务，组合时记录实际文件、状态与版本。母 Skill v0.5.1 只增加这一说明；核心脚本及本轮工程验证对应的字节未改变。完整记录见[本轮验收](../evals/director-workflow-v0.5/acceptance.md)。

母 Skill 由宿主 Agent 编排可用的图像与编辑工具执行制作，脚本提供可复查的规范、任务和交付基础。它不自带图像模型或 Photoshop 服务；本轮没有生成新艺术资产、操作 PS 或替总监批准作品。工程验证已经执行，团队品质与效率的改善仍应在真实制作批次中衡量。

## 使用入口

主美可直接说：

> 使用 art-director。先看我已有的资料，帮我写出可以评审的项目定位和设计规范，再带我逐步明确各类组件、家族和样板。保留探索空间，把确定的判断做成能交给团队执行的项目包。

成员拿到包后可以说：

> 读取这个项目包，按其中的 HUD 家族准备按钮三态首件。沿用主美的共同规则和参考，列明这次变量，继续制作与交付检查；把需要主美决定的差异集中告诉我。

Agent 负责文件、命令、版本和记录。专业判断由项目材料与实际评审建立，成员沿已授权规则工作，不必每次重新表达整套风格。
