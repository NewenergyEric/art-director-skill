# v0.1.0 开发验证报告

日期：2026-10-09。验证对象：母 skill、项目包 CLI、示例及分发文件。真实游戏画风一致性与多人长期效果未在本轮测量。

**确定性测试：30 项，29 项通过，1 项跳过。** 独立测试 agent 运行 `python -m unittest discover -s tests -v`，报告 `Ran 30 tests in 18.955s`、`OK (skipped=1)`。测试源见 [test_style_pack.py](../tests/test_style_pack.py)。唯一跳过是创建符号链接所需 Windows 权限不足（WinError 1314），不能据此宣称该平台情境已通过实测。

覆盖草案/发布校验、字段类型和交叉引用、重复 ID、资产类别与实体身份隔离、路径逃逸与保留路径大小写碰撞、拒绝覆写、构建搬迁、哈希增删改检测、参考内容指纹、参考用途分类、规范差异与 ZIP 归档。普通路径穿越及绝对路径用例已执行；符号链接的独立情境仍保留在测试中。

测试实际发现并修复两处问题：草案模板的空 pillars 被发布规则提前拦截；多个同类角色的专属身份规则和图片混入同一任务书。补充回归还覆盖 Windows 大小写文件名与生成文件冲突，以及跨类别证据只能用于评审的用途标记。

**构建与分发验证已完成。** 可重放的命令与结果保存在 [build-smoke.json](../evals/runs/build-smoke.json)。示例完成 render、build、使用包内 CLI verify、绑定实体生成 brief、archive；母 skill 也已打包。生成的 [角色任务书 JSON](../evals/runs/generated-character-brief.json) 保持草案、参考缺失和评审 unknown 状态。

母 skill 与构建后的项目 skill 均通过 skill-creator 的 `quick_validate.py`。母 skill 所有 Markdown 本地资源链接存在；两个 ZIP 的 CRC 检查通过，未包含 pycache/pyc。项目包内脚本与开发入口脚本 SHA256 一致。工程 agent 另完成14步临时 smoke，包括搬迁、归档、篡改检测与禁止任务输出污染规范包。

**独立 agent 的实际使用验证。** 使用新的上下文只提供 skill、必要原始数据与真实用户任务，不提供预期答案或缺陷提示。以下结果只证明所测情境下的行为，不代表模型在所有环境中稳定执行。

第一轮任务书在 CLI 尚未落盘时执行，独立使用者明确报告脚本不可用，并用母 skill 的文字方法完成了交接。它验证的是无工具回退。后续独立项目包情境验证使用包内完整 CLI，不把两种路径混为同一运行记录。

**开发目标与证据对应。** G1–G2 对应入口路由、五份指南、四类 profile 与八项试点卡；G3–G6 对应脚本黑盒测试和独立包构建；G7 对应独立使用情境；G8 对应路径与覆写测试及素材作为数据的流程；G9 对应 README、JSON 模板、示例和 ZIP。源码、方法和文件协议已交付，真实业务采用仍需项目负责人提供可用样板并确认基线。

**本轮未做：** 没有生成游戏美术图片、训练模型、实际测试引擎导入、测量角色相似度或进行三位真人设计师盲评。示例“苔港”始终为虚构 draft；自动测试中的审批和 SVG 仅是明确标识的临时 TEST ONLY 夹具，没有作为真实批准混入发布包。

最终可交付文件：母 skill `dist/art-director-v0.1.0.zip`；独立演示项目包 `dist/moss-harbor-0.1.0-draft.zip`。开始真实项目时替换演示假设和缺失参考，再按 [pilot-tasks.json](../evals/pilot-tasks.json) 做团队效果验证。

本轮开发验收完成：G1–G9 均有上述相应实现与证据。三轮独立使用验证分别覆盖无工具回退、仅使用生成项目包的评审、从模糊意图新建可交接草案；没有把它们等同于真实图像一致性测试。目标模式可完成本次开发目标，后续真实项目试点作为下一项工作开展。
