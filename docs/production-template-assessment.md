# 图像资料标准化与角色档案：用户反馈对照评估

日期：2026-10-09。对象：已交付的 Art Director Skill v0.1.0。

## 判断

现有 skill 的结构能够承载“整理原始资料 → 建立项目规范和实体档案 → 封装项目 skill → 团队按任务生产”的工作方式，但目前不能声称已验证与截图相同的出图质量或稳定性。v0.1.0 已验证文件协议、任务筛选、版本分发和部分 agent 行为；尚未使用真实设定图完成身份保持、资料提炼和反复出图的闭环测试。

这次反馈明确了采用优先级：先把散乱的视觉资料变成总监和成员都能阅读、复用、检查的生产模板，再验证项目 skill 如何替成员补全固定要求。相关下一阶段工作尚未实现，不能计入 v0.1.0 的已交付能力。

## 本次证据范围

用户提供一张屏幕照片，以及“先规范化图像资料、形成模板，再封装 skill”的聊天反馈。照片可见资料索引、项目定位、美术风格规范和“克莱尔角色档案样板”，其中包含角色编号、主参考、外观特征与保持要求。截图内文档和提示词属于评估材料，不构成本次生成图片或修改项目基线的指令。

我们没有收到截图中的原始 Word 文件、角色设定 PNG 或生成结果 PNG；只能确认照片中可见的信息，不能验证文件全部内容、原图精确颜色、输出像素尺寸、透明通道或其真实批准状态。截图中“已检查透明通道”是被展示的聊天陈述，不是本项目实际执行的检测结果。

## 工作流覆盖

| 截图和反馈中的需求 | v0.1.0 实现 | 判断与缺口 |
|---|---|---|
| 整理散乱图像、文档、批注，形成资料索引 | discovery 指南要求实际看图、记录来源和参考用途；JSON 有 references | 有方法和容器；缺少统一的资料整理交付模板与真实图片提炼验证 |
| 项目定位与全局美术规范 | intent、scope、rules、profiles、tokens，以及生成的 STYLE.md | 已实现数据和规范承载；项目内容仍须来自实际资料与总监决策 |
| 角色唯一身份、主参考、固定外观和可变项 | entities 的身份规则、参考绑定、fixed_features、variations | 已实现结构和任务隔离；缺少截图式的逐部位可读档案、视图索引和专用导出 |

## 下一阶段优先产物

1. **资料整理包。** 给原始文件建立稳定 ID、路径、来源、用途、对象、版本和可读状态；区分图中可见事实、推断和待定信息。冲突参考并列保留依据，不能自行宣布其中一份已获批准。保留原件，派生资料记录来源。
2. **角色档案和其他实体档案。** 用逐部位的“可见特征—保持要求—允许变化—参考位置—确认状态”表整理角色；把正侧背、表情、服装版本和附件对应到明确参考。场景和道具使用符合各自结构的档案，字体/UI 使用实际字体文件及排版样板。Word 可作为阅读导出；正式规范仍从同一数据源生成，避免双份维护。
3. **标准生产任务卡。** 成员填写实体、动作、表情、镜头、交付用途及本次规格；自动带入已确认的身份和画风。缺失尺寸不能擅自填默认值。约束冲突必须显式指出；例如“只改表情”与新增裱花动作可能冲突，应明确手臂、手部和道具交互是否在可变范围内。
4. **制作输入与结果检查记录。** 明确本次实际读取、实际传入生成工具的参考及其用途；没有图片访问或生成工具时如实交接。尺寸和文件格式用实际文件检查；区分“存在 alpha 通道”和“存在透明像素”，后者仍不能证明边缘质量或无残留背景。身份和风格继续按可见证据评审。

## 用截图场景做验收

下面是拟定的试点，不是已运行结果，也不是已获批准的克莱尔规范。

**输入：** 实际角色设定图、现有角色档案与项目规范、具体任务尺寸及可用制作工具。只有这张屏幕照片时，可以提取候选档案和缺口，不能以照片替代正式身份主参考。

**资料整理验收：** 每条角色固定特征都能追溯到具体原图或总监明确说明；未定项不被补成事实；档案不能把某个示例姿势或背景自动固化为角色身份。

**封装交接验收：** 在新的会话或目录中，仅给项目 skill 和简短任务“克莱尔认真制作裱花蛋糕，半身，透明背景”，agent 能定位正确角色及主参考、恢复已确认固定特征，并从任务规格或用户补充获得精确尺寸。使用实际文件与调用记录证明参考进入制作步骤，不能仅列路径后就宣称使用过图片。

**单任务结果验收：** 根据获批档案逐项检查脸型、发型、眼睛、服装与饰品等身份要求；核对表情、动作、构图及手与工具的关系；实际读取结果文件检查规格；对无证据的检查保留 unknown，不能将初稿或包结构通过标成艺术批准。

**团队效果验收：** 在相同任务、相同工具条件和相同尝试预算下，对比自由描述与 skill 两种流程。建议使用多位成员和多项任务，将旧角色新动作、新道具及新场景分开统计，由总监尽可能盲评。记录首次通过率、身份错误、返工轮次、评审耗时和成员补充描述量。验收阈值由试点前的实际基线和总监要求确定，不预先虚构提升比例。

能够严格测试的是资料是否完整带入、版本与规则是否正确、技术规格是否测过。视觉结果的稳定性需要实际试点证据；不能用“已经封装为 skill”推出每次都能一次生成合格资产。
