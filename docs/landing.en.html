Read the workflow

The director supplies existing work, references and notes. The agent drafts the rules and prepares representative samples for review. Confirmed decisions travel in the project pack. A teammate gives that complete pack to their own agent and describes a task. The agent uses its rules, references and version, then creates through the available tools. Review identifies specific differences and explains revisions. Shared issues return to the director for a new version.

01

I’m setting
the art direction.

Put existing work, references and review notes in a folder your agent can read. Start with what you have.

Use $art-director. Here are our designs, references and notes. Draft our art direction, then help me define the character, environment and UI requirements. Prepare samples for me to review and package the result for the team.

You get A substantive draft, decisions needing your input, a sample plan and a shareable project pack.

02

I’m creating
within the rules.

Give your agent the director’s complete project pack. It contains the project’s rules and materials.

Read this project pack. Create the default, pressed and disabled button states using its UI rules. Show me a first sample, explain which rules you used, and list anything still needing a check.

You get A versioned task, relevant references, a first sample and a check record. Creation uses the tools available in your agent.

Keep the conversation going: Check these assets against the rules. Show me what needs changing and why.

Can I build on an existing design system?

Yes. The agent starts with your current rules and samples, identifies gaps and helps you fill them. Discuss changes naturally; the agent keeps the guides and project pack in sync.

Who decides whether the design is good?

The director owns direction and release decisions. The Skill organizes the evidence, checks against the rules and explains revisions. Passing a technical check is separate from visual approval.

What happens when the project changes?

The director publishes a new version. New tasks use it; existing tasks keep their original versions so their rules do not shift midway.
