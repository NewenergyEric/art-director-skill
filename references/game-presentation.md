# 把游戏内容做成宣传画面

用于商店截图、README 动图、项目介绍与宣传视频。先沿用项目的视觉规范和真实资产，再决定传播构图；不要给所有游戏套同一种描边、绳结或配色。

## 先看用户会看到什么

读用户指定商店页的实际图片，记录标题在卖什么、角色动作、前中后景、界面与道具的关系。区分可借鉴的表达方法和不能当成自己项目素材的角色、标识、剧情。不能只读页面文字就声称完成了视觉研究。

先区分宣传对象。介绍游戏时让玩家看见要做的事；介绍 Art Director 时说明主美如何交接方向、成员如何制作一致的组件，游戏画面是证据。不要用押韵或拟人的口号替换产品用途。

一幅画面只传达一个具体结果。图片已经说明的动作不再配一段解释；标题、副标题、角注不反复说同一件事。技术限制与复现入口放在画面外的正文。保留能帮助读者理解或行动的信息，删掉自我评价和流程独白。

## 文字也是资产，但仍须可读

- 主标题先根据画面选择字形，再决定是否需要倾斜、描边、填色或厚度；这些效果不是固定配方。笔触、轮廓和时代感要与角色、材料、故事气质相容。在真实画面比较候选，不能先套默认粗黑体再靠特效补救。
- 标题优先压在有意预留的画面空间中；人物和道具可以跨框，但不能遮住脸、手、主标题或关键操作。
- 小字、安装步骤与正文保持清晰。游戏按钮、对白和数值采用对应项目的 UI 字体规范，不直接沿用网页标题。准确文本保留可编辑来源；生成字形需核对，不能将错字当成风格。中文描边要查看笔画相交处，英文要看字距与词形，多语言可有不同字形方案。
- 需要木牌、按钮、绳索或装饰框时，从项目的材料与轮廓出发制作独立透明元素。不要把整张宣传图冒充可编辑拆层。

## 让构图说明关系

避免连续采用“左侧讲解＋右侧手机截图”和三张等宽卡片。按用途切换满幅场景、角色前景、道具链、真实界面局部、修复对比或连续故事；统一视觉语言不等于重复布局。

效果服务事件和角色意图。使用实际动作序列、绑定动画或生成动画时，按[连续场景与生产交付](scene-production.md)检查节奏、接触和身份；不能只给所有图片同一段悬浮。剧情、数值与操作需能追溯到原型或标清为宣传示意。宣传画面展示出来的完成度，不能超过它实际具备的资源与行为。

最后看真实导出：缩略图标题能否读懂；同一段的画面是否支持标题；裁切是否漏掉主角或归船；放大后文字与 alpha 是否干净。MP4、GIF、静态备用图与网页要从同一来源更新。视觉观察、自动检查和用户认可分别记录。
