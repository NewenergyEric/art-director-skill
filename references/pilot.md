# 用真实资产验证项目 skill

试点回答：同一批原始资料、同一任务和制作条件下，使用项目 skill 是否伴随更少的身份错误、更高的首次通过率、更少的追加制作。没有原图、档案或实际生成结果时，只能完成试点准备，不能报告改善。

## 先固定本轮材料和任务

收集用户授权使用的原始角色图、档案原文件及本轮任务。用文件哈希固定材料，保留文件名、来源和版本；Word 按真实页码/段落定位，图片按文件及局部位置定位。屏幕照片可以作为候选线索，但其拍摄角度、压缩、遮挡和缺页需要记录，不能替代原文件或证明正式批准。

使用 [角色档案模板](../templates/entity-dossier.template.md) 分开记录可见事实、规则、允许变化及证据位置。看不到的背面、被遮住的饰物或未提供的档案页记为 unknown；不可凭经验补成“应当如此”。现有明确用户指令和授权直接沿用，无需为试点增加审批环节。若规则只是从图中推断，保持 proposed；明确记录真人、AI 辅助和实际决策者，不默认 AI 是美术总监。

用 [制作任务模板](../templates/production-task.template.json) 固定用途、实体、视角、目标尺寸、必要技术要求、允许变化、输出数及总预算。选择真实制作需求中能观察到身份的任务，例如已获授权的新姿势；不要预先填造真实提示词或生成结果。缺少决定任务内容的材料时列出缺口，准备其余字段，不假装已执行。

## 两组只改变 skill 的使用方式

| 条件 | A：原始资料与自由描述 | B：项目 skill |
|---|---|---|
| 原始材料 | 同一原图、同一档案、同一任务文本，实际附入工具 | 相同原图、档案与任务，使用规范、实体及参考角色绑定 |
| 任务信息 | 执行者根据原始资料自由编写描述 | 依据固定版本规则编译描述 |
| 派生信息 | 不提供 B 的规则摘要、标准提示或任务书 | 规则只能来自两组共同材料及已有共同授权；新增事实须先同步两组或另起试点 |
| 制作条件 | 与 B 相同模型/版本、工具、尺寸、输出数、生成次数或费用/时间预算 | 与 A 相同；记录工具对参考输入与参数的实际支持 |

资料相同不等于工具实际收到相同资料。每次调用都保存真正输入的文件/参考 ID、哈希、角色、输入方式和工具回执；工具未收到图片时不能仅凭提示里写了路径算已附图。两组均可读取原始档案，不要通过不给 A 原图来人为制造优势。A 的原始资料不能夹带由 B 生成的规则或标准提示。

冻结项目包版本/fingerprint、档案版本、原始任务和验收口径后再制作。A 和 B 使用隔离上下文，A 不读取 B 提示、结果和反馈；返工反馈量和形式也应一致。不要在看过某组结果后修改另一组标准。中途必须变更时保留原记录并另标阶段，不覆盖旧结果。

为任务与条件组合随机排序，保存随机化方法、随机种子和实际执行次序。若同一执行者参加两组，采用交错/平衡顺序并记录先前接触 skill 的情况；已知规则无法通过开新对话从真人记忆中清除。分组结果为 `cohort=ai_proxy`（AI 代跑）或 `human_team`（真人成员），分别统计；代理测试不能写成团队生产验证。

输出统一赋无组别含义的盲审 ID。映射由协调者保存，评审人先只看盲审文件、共同的验收依据与任务目标，提交判断后才解盲。评审人知道组别、能从文件名猜到组别或亲自生成过该图时，记录 `blinding.achieved=false/unknown`，不能声称完成盲审。审查依据可包含已冻结的身份判据，但不能把 B 的提示泄露给 A 执行者。

## 每次尝试留下证据

[试点记录模板](../templates/pilot-records.template.json) 的 `records` 初始为空；`record_template` 和 `attempt_template` 只是待复制结构，不参加统计。每条 record 是一个任务、一个参与者在一个条件下的一次实验单元。分配了但未执行的任务使用 `execution_status=not_run` 且 `attempts=[]`；真实生成/编辑调用发生后才追加 attempt，序号从 1 连续增加。工具失败也保存该次尝试，输出路径填 null，并记录失败原因。

每次保存实际提示记录及哈希、工具/模型/版本/参数/seed、实际参考输入和原始输出哈希。未返回的模型版本或 seed 填 null 并说明原因。不能用模板配方值冒充实际设置。若一次调用返回多图，完整保留所有图及其选择过程；`attempts` 统计调用/修改尝试数，不是图片张数。两组固定每次输出数，避免只交各组最好的一张造成选择偏差。

分别评审 identity、style、task、technical，使用 pass/fail/unknown 并留下可追溯证据。身份违规需定位到具体部位、规则、原图/档案位置和输出区域；不可观察或规则尚未明确时为 unknown，不自动判违例。原始图未看过，不能只根据描述给身份 pass。

视觉证据记录实际打开的图、显示尺度、参考对比、评审者类型与具体观察。技术证据记录执行过的测量/工具、命令或设置、实测值与要求值；“看起来能进引擎”不能替代引擎导入或实际场景测试。概念图只按预先固定的概念阶段技术条件评审，不临时加引擎门槛；若任务目标是引擎资产却没有工程测试，technical 保持 unknown。AI 评审只是其明确身份下的判断，真人总监结论只有真实决策记录才能支持。

## 统计口径固定后再跑

在仓库根目录运行 `python scripts/pilot.py summarize RECORDS.json --out NEW_SUMMARY.json`（替换实际路径；输出文件不得已存在，先查看该命令 `--help`）。未运行模板应返回样本量 0、比率 null，不能显示 100% 通过。

本地资料与图像检查可按下列命令调用；输出父目录须已存在。`INPUT_DIR` 是原始素材所在目录，`NEW_INTAKE_DIR` 必须在原始目录之外且尚不存在。尺寸应替换为任务规格。`intake` 的“已读”表示文本提取或图片解码成功，不表示 agent 已视觉理解图片；`check-image` 只检查存储尺寸和首帧透明像素，不判断背景抠图质量、身份或画风。DOCX 只提取正文段落和表格文本，不提取嵌入图片与排版；需要看图时另行打开原件或用户提供的原图。

```text
python scripts/pilot.py intake --input-dir INPUT_DIR --out NEW_INTAKE_DIR
python scripts/pilot.py check-image OUTPUT.png --expected-width 1024 --expected-height 1536 --require-transparency --out NEW_CHECK.json
```

以上 `pilot.py` 是母 skill 附带的工具；既有项目包不会自动获得它。跨环境调用时确认脚本真实位置与 Pillow 是否可用，缺少能力就把相应检查记为未检查。`summarize` 只按记录进行算术汇总，不重新打开生成资产或验证文件哈希；记录中的评审与产物存在性须由实际制作及评审步骤提供证据。

- **已运行样本 n**：同一条件与 cohort 内，`execution_status` 为 completed、failed 或 incomplete 的 record 数。failed/incomplete 不能从分母删除；not_run 另报且不计入已运行分母。
- **首轮通过率**：第一条 attempt 有实际输出路径，且 `required_review_criteria` 中所有项均为 pass 的 record 数 / n。缺失评审字段按 unknown；未知、工具失败和只在后续通过均不算首轮通过。n=0 时为 null。默认四项全纳入；如项目需另一指标，必须开跑前固定，并明确说明分母与范围。
- **身份违规**：报告至少一次 identity=fail 的 record 数及其占已运行 n 的比例；同时报告 identity=fail 的 attempt 数 / identity 已明确评为 pass 或 fail 的 attempt 数，另报 unknown 数。两种分母意义不同，不互换；没有评审不能叫“零身份错误”。详细部位违规数可以单独留档，不能当作脚本的任务级违规率。
- **追加尝试/返工**：每条已运行 record 的 `max(0, len(attempts)-1)`；报告总数、均值与 n，n=0 均值为 null。计入失败的实际尝试，不把计划中的预算填入 attempts。手工修订也须记录其方式与工时，若与生成调用混合则分开解释，不能把返工次数直接等同时间节省。

公平性逐项记录原料、任务、工具/模型版本、尺寸、预算、反馈、次序和盲审是否 matched/mismatched/unknown。仅当双组都有已运行样本时，展示 B-A 的描述性百分点差。样本少、条件未匹配或公平性 unknown 时，报告观察结果和限制；不宣称 skill 导致改善。用户若继续授权真实团队试点，再积累真人记录，保留 AI 代跑结果作为独立 cohort。

最终交付包含原材料清单及缺口、固定任务与版本、两组实际输入、全部输出与哈希、盲审和测量证据、失败/未知/未运行记录及统计结果。准备工作、结构校验、视觉通过和技术可用分别汇报。
