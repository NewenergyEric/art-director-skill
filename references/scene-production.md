# 连续场景与生产交付

当一套静态资产已经成立，先补玩法与状态覆盖，再增加数量。把玩家事件拆成资产和组合关系：材料提交 → 修缮动作与效果 → 场景修复；灯具提交 → 点灯与昼夜；归航 → 船、水面反馈与奖励。每一项沿用项目规范，事件与数值是本次原型变量。

规范至少明确相机与地标、角色接触点/地图尺度、状态保留项、特效形状/颜色/时长、UI 遮挡范围、减少动态与中断行为。生成状态图后要比地标；宽高一致不证明几何一致。单张动作素材不能写成一套动画，代码位移不能写成骨骼动画。

工业化的重点是任务、输入、依赖、版本、组合和证据可追溯；不是承诺一次全自动生成就合格。按首件风险排列依赖，记录每次实际工具输入；复用未变资产，将变动影响传到下游。共享审美仍只有 `style-pack.json`，生成计划不复制一份颜色与规则成为新标准。

可选配套 `game-art-production` 有两条输出：常规资产/组合交付，以及 Compositor `.comp` 分层场景。它是独立安装的执行入口，项目包仍由这里维护。Compositor 是图层编辑器，不替代图像模型、动画软件或引擎；用户不需要安装它才能用主 Skill。

发现共性问题时，新建候选版本，记录哪些规则与资产受到影响，重建包后再冻结生产计划。演示、素材库、视频与导出共用同一场景配方。交接中区分技术完整、自查结果、真实主美批准和原生/引擎检查，不把其中任何一步代替其余步骤。
