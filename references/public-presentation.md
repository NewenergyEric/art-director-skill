# 公开表达与视觉记忆

这套规则只用于 Art Director 自身的 README、介绍页、演示片和工作台。它不是安装后替任何项目预设画风；项目仍由主美从自己的资料、样板和专业判断建立规则。

## 唯一主张

所有公开入口先回答同一件事：**一个团队，一份视觉记忆。** 英文固定为 **One team, one visual memory.** 这里的“视觉记忆”指同一项目版本中的视觉语言、组件与资产家族、代表样板、允许变化、交付要求和评审记录。它的结果是让成员与 Agent 在每次交付时读到同一份依据。

不要再使用“把判断交给团队”“Your vision. Their direction.” 之类容易暗示负责人把判断权转交出去的句子。主美始终负责专业判断和发布决定；Skill 负责把这些判断组织成能共享、能调用、能检查的项目记忆。

## 稳定的视觉语法

- 色彩以海军蓝 `#001f3f`、青绿 `#007d86`、薄荷 `#92e4da`、雾白 `#f5f9fb` 为核心。候选作品可以带入自己的颜色，但界面框架不随案例换品牌。
- 字体使用仓库内 OFL 许可的 Noto Sans SC 可变子集。正文保持克制；主钩子可以用 380 与 820 的粗细反差、轻微倾斜、错位和与画板重叠来成为构图的一部分。
- 空间感来自前中后景、透视、光带、遮挡和连续缓动。避免逐页切换、卡片依次出现的幻灯片感。
- 文案先说团队获得的共同依据，再解释主美如何建立、成员如何调用、交付如何保持同一版本。技术名词只在工程入口展开。
- 动画和页面都使用真实候选作品、规范文件与交付关系作为视觉对象；不添加与产品能力无关的装饰性仪表盘。

## 四种构图，不复制同一模板

同一个设计系统允许页面各自承担不同任务：

1. **产品封面 / README 动图**：深色空间海报。大字压在画板前，三层作品与 `STYLE.md → SKILL.md` 形成深度，六秒轨道闭环。
2. **产品介绍**：编辑式长卷。用超大关键词、错位段落、细线和一条空间影片讲清“建立—校准—交付”，避免把每段都装进同样的卡片。
3. **主美与成员工作台**：深色项目记忆侧栏配浅色操作区。信息密度高，但首屏仍用一块有空间层次的钩子说明当前角色和结果。
4. **工程调用路径**：海军蓝网格蓝图。节点、文件和版本关系是主角；保留技术秩序，同时用同一字体、颜色与共享版本隐喻连接产品叙事。

团队并行演示使用横向生产墙，作为第五种功能构图；它继承上述字色和层次，但不再复制产品封面的海报布局。

## 动效与媒体

- GitHub 只保留一组当前六秒 GIF，中英文各一份，800 × 450、20 fps、单个不超过 4 MiB；另配静态 JPG 给 reduced motion。
- 网站使用相同源构图的 18 秒 H.264 MP4，中英文各一份，30 fps、faststart。旧 12 秒 GIF、70 秒影片和四组旧分镜不再作为公开入口。
- 六秒 GIF 的首尾必须连续。大标题保持足够长的停留；画板持续小幅位移、转动和呼吸，不用突兀换页。
- 页面动效尊重 `prefers-reduced-motion`、Save-Data、页面可见性和离屏暂停。功能页面默认不自动播放。

## 发布前一致性检查

逐一检查 README、中英文动图、产品介绍、主美工作台、成员任务、团队生产和调用路径：

- 核心句是否为固定中英文版本；
- 是否仍引用旧 GIF、70 秒影片或四组旧分镜；
- 字体、色板、按钮与焦点状态是否来自共享视觉语法；
- 页面是否有自己的信息结构，而不是重复产品封面；
- 移动端标题是否截断，正文是否可读，交互与链接是否有效；
- 示例是否继续标明候选、模拟、未检查和真实证据边界。

修改公开文案或构图后，从 `motion/src/DepthShowcase.tsx` 重新生成 GIF、MP4 与静态海报，更新媒体清单，再运行页面与 Skill 验证。
