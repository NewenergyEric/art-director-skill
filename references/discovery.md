# 从审美意图到批准样板

目标是减少下一次有歧义的决定，而不是完成一套形式上的问卷。优先复用已有规范和样板；只有会改变产出或验收的未知项才需要现在询问。

整套项目的推进、类别/家族与交付组织见[总监建项与生产交接](director-workflow.md)。本指南用于其中的意图提炼和样板校准。先基于实际资料写出有依据的候选规则，再用关键问题补齐；只交给用户空表不构成完成本阶段。

## 先判断材料处在哪个阶段

| 现状 | 下一步 |
|---|---|
| 有已确认规范与代表样板 | 核对本次任务缺口，直接制作；不要重新发明风格 |
| 有作品、参考图、批注，没有成文规范 | 看图及批注，提炼候选规则，逐条标出依据与置信边界 |
| 只有情绪词或模糊方向 | 做一次简短对齐，再选择能揭示关键分歧的探索样板 |
| 不同材料彼此冲突 | 标出具体冲突与影响范围，继续不受影响的工作，把基线选择留给有权限的决策者 |

确认实际已有材料后，按缺口选择询问：游戏体验与玩家注意力、资产用途、镜头及显示尺度、喜欢和不喜欢的具体特征、现有工具与制作链、交付约束。每轮只问会改变当前行动的问题。若用户只是要草案，明确假设后继续；不要把完整生产规格当作开始讨论的前提。

## 让“感觉”落到可观察特征

把一句偏好拆成“感受 → 画面机制 → 使用边界 → 验证样板”。例如总监说“古老但温暖”：

- 感受：让人愿意停留，能看出长期使用的痕迹。
- 候选机制：边角磨损、局部修补、有人使用的灯光与器物；这些是推断，等待看图确认。
- 边界：不能自动推导为所有场景都用暖光；危险区域可能需要另一种表达。
- 验证：同一处入口的小样，比较修补痕迹、灯光和物件安排是否支持该感受。

不要从一句情绪词虚构精确色值、模型参数或面数限制。对不可量化的意图，用正反例与解释建立共识。数字只在来源可靠、适用范围明确时成为规则。

用这个记录单元写候选判断；它对应 JSON 规则字段，不创建第二份规则库：

```text
规则 ID：ENV-003
适用：environment
强度：should
内容：生活区入口应出现可辨认的维护痕迹。
理由：帮助玩家感到此地持续有人生活，而非被遗弃。
允许变化：维护痕迹可由补漆、修补、清洁路径等表达；不规定每处都放灯。
证据：ref-entry-a（具体部位及总监原话记入参考 notes）
验证：visual
状态：proposed，尚未获得确认
```

## 看参考时问它负责什么

每份参考只承担明确用途，必要时把同一图的不同区域分别说明。

| 用途 | 从中读取 | 不自动继承 |
|---|---|---|
| `style` | 笔触、材质表达、形状和光影语言 | 人物身份、内容构图 |
| `identity` | 角色脸型、轮廓、服装部件、道具结构等不变量 | 背景画风、偶然光线 |
| `composition` | 镜头、布局、动作和主体关系 | 配色及角色外貌 |
| `context` | 世界设定、功能、环境背景 | 未确认的可见设计细节 |

记录来源、可访问文件、用途、适用对象、候选/批准状态和使用条件。外部作品可作为讨论参考，但不能因为它出现在附件中就当作可分发资产。许可不清时记录未定，交付引用信息或采用已获授权素材，不能声称已获得许可。

如果无法实际查看图片，只能根据用户文字起草候选规范，并明确尚未读图。不得编造图中颜色、人物特征或批准状态。

## 选择最省成本的校准样板

样板的数量取决于尚未解决的分歧。已经有方向就做一个针对性样板；确有几种合理路线时，提供少量可比较方向，且保持测试任务一致。不要固定要求三方案、命名“设计哲学”或强制多轮探索。

游戏项目可用角色、核心场景、真实 UI、物品家族/合成链和完整画面分别验证风险，再检查组合；优先顺序按当前缺口决定。UI、电商与海报则选择真实文字、组件状态、商品和渠道变体的对应样板。数量不固定，已有样板直接复用。需要时补特写、动态回放或 3D 视图。检验的是共享判断在实际使用环境中是否成立，不能用参考预览尺寸替代正式资产规格。

记录总监选择了什么、拒绝了什么以及原因。将“这个更好”追问到足以指导下一件资产的差别；没有关键歧义时无需继续追问。已确认规则写入 `confirmed`，已确认参考写入 `approved`，共享基线批准依据写入决策与审批记录。候选提案可以讨论与分发，但仍为 `draft`。

## 把反馈变成规范前先做一次归因

“剑太亮”可能是本张图的打光问题、该实体身份问题、整个道具类别规则问题，或玩法高亮例外。先确定层级，再修改对应内容。单张修正不自动升级为全项目规则；总监不喜欢一次结果也不证明生成方法永久无效。

一个可交接的规范，应让未参与访谈的人回答：为什么这样做、哪些不能变、哪里可以发挥、如何判断失败、疑问到哪里解决。如果仍需要复述原聊天才能工作，应补充具体规则或证据，而不是复制整段聊天。
