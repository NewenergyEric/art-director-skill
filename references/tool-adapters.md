# 生成与检查工具适配

项目规范独立于生成工具。配方只描述已知可用的实现方式，不承诺任意模型都能同样复现风格。

## 根据实际能力选择路径

| 当前能力 | 可以交付 |
|---|---|
| 能读图，能生成/编辑图 | 用参考辅助制作，再对实际输出做适用范围内的视觉检查 |
| 能读图，没有生成工具 | 提炼规范、评审已有图、输出完整任务书及参考清单 |
| 能生成但看不到输出 | 交付生成结果并标记视觉未检查，安排可读图的评审 |
| 只有文字工具 | 起草基于文字的候选规范、整理任务书和结构检查；不声称看过图 |
| 有 3D 工具但没有目标引擎 | 检查工具能覆盖的模型条件，保留引擎导入为未检查 |

不要为了填补能力缺口自动安装插件、下载模型或调用收费服务。若用户已授权对应操作则沿授权范围执行。工具缺失不妨碍交付有明确输入和验收办法的任务书。

## 每次生成前做一个输入映射

执行参考续作、跨题材延展或定向修正时，先用[制作协议](asset-production-protocol.md)明确继承范围与实际用途，再映射到工具；不要让工具默认的“精致化”改变项目判断。

将相关规则转成工具支持的约束，不把整个参考目录作为一组未区分的图片输入：

```text
本次任务：hero 的待机侧面视图。
风格输入：ref-paint-style → 保留笔触和材质表达。
身份输入：ref-hero-front、ref-hero-side → 保留已确认的脸、发型及其他身份特征；衣装是否保留按本任务明确的变化处理。
构图输入：ref-idle-layout → 仅用于动作与画面位置。
上下文：任务书中的世界设定文字 → 不覆盖已确认的身份规则。
输出：项目已确认的规格；未知项明确未定。
```

参考必须通过工具真实支持的图像输入字段、附件或对应节点传入；提示词里写一个本地路径不等于模型接收到了图像。先确认文件能访问并实际查看需要理解的图，再调用工具。无法传入多用途参考时，减少任务复杂度、采用分步编辑或提供人工操作任务书，明确限制。

按参考续作时，输入映射还要说明哪些表现**不能增添**：结构层数、体积厚度、纹理密度、高光强弱等依实际参考确定。不要用通用“高端、超精细、写实、3D”修饰覆盖这些判断。失败稿即使身份正确，也可能把错误体积和光照带进下一轮；反复减纹理仍无效时，直接回到原参考生成，或只使用失败稿中确有必要的身份信息。不能把反例作为未区分的正向输入。

工具不支持独立负面提示、种子、参考权重或透明背景参数时，不虚构这些功能。可以用普通语言表达避免项，但准确记录采用的方式。需要精确构图、身份或局部修正时优先考虑工具实际支持的编辑控制，不假定单次文本生成能锁定这些条件。

## 记录可复现信息，不许诺绝对复现

把实际工具和版本（可得时）、模型/工作流标识、输入参考、提示词或编辑指令、已使用参数、输出位置和限制写进任务交付记录。参数值来自真实执行或用户提供的已验证配方，未知时留空或明确说明。

种子、相同提示词或相同工作流并不自动保证不同模型版本和环境给出相同图。记录用于追踪差异，不能替代输出检查。模型、字体或其他素材的来源和使用条件也应随配方保留。

## 生成以后

查看真实输出后按 [评审与修正](review.md) 逐项记录；必须区分风格、实体身份、构图和技术结果。更新某个参数若同时破坏另一项硬规则，应保留冲突证据，不能为了追求相似度牺牲用途。

提炼新配方时，只把在本项目实际试过的结果标为已验证。可保存候选配方供讨论，但不能把下载来的节点图、他人报告或猜测参数直接宣传为本项目可用。没有真实生成与评审的示例应标明为说明性草稿。
