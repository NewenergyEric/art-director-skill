# 潮灯小镇 · 主美交接说明

本包是原创虚构项目的 0.2.0 试作规范，用来检查一份视觉记忆能否交到角色、场景、UI 与物品制作中。所有美术方向为 proposed/candidate，未代签主美批准。用户授权完整跑一遍，并明确反馈原画风、物品和界面不像合成游戏；本版按该反馈重新校准，而非只追求与旧图一致。

## 游戏与这一轮工作

竖屏休闲 Merge-2 修复游戏：点灯匠工作箱取一级灯，两件同级灯合成下一级，交出订单需要的灯，回到小镇看旧灯房修复。这里只做一个可检查的美术/交互切片；7×7 棋盘、390×844 画面、体力与金币是本次试验设置，不声称做过商业数值、留存或设备测试。

主美首件：阿澜默认站姿、未修复灯房、L1/L2 灯、工作箱、真实文字与按钮状态的 UI 源码。成员后续任务：阿澜挥手、同灯房修复后状态、L3/L4 续作、新订单及缺件/可提交/已提交状态。制作时只用本包与这段新任务，不需原聊天。

## 共同语言及类别差异

清楚饱满的体块、柔和宽高光、干净的局部色、上左光源；海绿/奶油/蜂蜜黄形成灯具与建筑母题，角色黄披肩/靛蓝工装/珊瑚鞋承接暖冷关系。布料不需要变成搪瓷。角色允许脸部表现比棋子丰富，地图允许空间深度；不得把宣传画细密笔触、金属摄影反射复制到 48 px 棋子。

地图是俯视三分之四空间；角色是剧情对话立绘，界面叠放，不冒充同镜头地图行走精灵。需要地图角色时另做对应镜头样板。棋子是轻俯视单件，不能机械继承地图镜头。

## 成员应继续的内容

- 角色：保留脸、暖肤、棕眼、深蓝大块短卷发、约 5.5 头身；默认服装不变，本次只改为微笑挥手。参考 character-base.png。
- 场景：保留机位、建筑体量、门窗数量位置、灯徽、海岸与木台。修补门前两块木板、打开前面两扇窗、点亮门灯，减少与任务无关的变化。参考 workshop-before.jpg。
- 合成链：L1 圆腹矮油灯 → L2 宽体提灯 → L3 圆镜探照灯 → L4 短粗锥形航标。两件同级合成下一件。成员生产 L3/L4，继承 L1/L2 的大色面、侧厚、柔和高光和珊瑚控制钮；细杆、金属噪点和细小缝线不再采用。工作箱是生产器，不能混在可合成链中。
- UI：继续 ui-kit.js 的组件；7×7 棋盘约 46 px 单格，64/96 px 另作检查尺度，不能拿放大展示代替实际格内检查。角色头像、订单需求、生产器闪电、选中框各自分工。数值、订单文字、等级角标由代码排版，不生成进图片。成员可扩至 L4 订单，必须提供缺件、可提交、已提交状态。

## 文件与操作

ui-first.html 与 ui-kit.js 是可编辑源文件，图像与 tide-sans.woff2 在同目录，OFL.txt 为字体许可。浏览器需要通过本地 HTTP 打开 ES module；不是把截图改扩展名。图片为独立 PNG/JPG，不是 PSD 分层文件。项目入口与核心脚本只需 Python 3.10+。

## 来源与限制

角色、地图、灯与工具箱由本次内置 image_gen 实际生成；generation-prompts.md 保存调用文本。未向生图工具提交竞品图片。旧细长灯具作为 counterexample，只用于评审。对照了 Microfun 官方 Google Play 展示的棋盘图：https://play.google.com/store/apps/details?id=com.mergegames.gossipharbor 。官方图仅用于观察小格占比、粗轮廓与操作区；未复制其角色、图标或 UI 素材。

本次由同一 Agent 在隔离目录模拟交接，不是独立真人团队实验。未验证引擎导入、目标机性能、完整动作、多视角、商业平衡和主美正式批准。
