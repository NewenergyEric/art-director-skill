## 已实际执行的检查

1. **核心程序：108 项测试，106 通过，0 失败，2 跳过。** 两项跳过来自当前 Windows 环境不允许创建符号链接；报告保留具体原因、输出和四个核心脚本哈希。后续最终打包核对这四个文件与测试时一致。
2. **两套完整案例：30 条断言通过。** 游戏包含 8 个家族，活动设计包含 5 个家族；生成 10 份手册，归档并解压项目包，仅用包内工具准备 6 个成员任务。共记录 29 次调用：28 次最终步骤得到预期结果，另保留 1 次示例组合请求缺少 `subject: null` 的初始错误。修正请求后重试通过，未更改核心脚本。
3. **页面：89/89 项检查通过，97/97 个公开文件路径存在。** 覆盖步骤、角色/渠道切换、键盘交互、输入转义、真实规范家族对应、素材原字节和已知保密资料排除。采用静态检查和 Node 模拟 DOM，未执行浏览器视觉验收。
4. **独立 Agent 实际使用。** 未参与实现的 Agent 没有继承开发对话，只获得 Skill 入口、一张原创方向图和现实需求：四人团队，平台/字体/预算等未定，需要建立角色、街景、合成物品、UI 与宣传制作体系。它读取图片、写专业初稿、构建/校验/归档项目、从解压包独立建工作区，创建 6 个任务并验证恢复和范围筛选。最后 18 个步骤均得到预期结果，10 项语义核对通过。

独立试用的一次验证脚本把 release 拒绝的预期退出码写成 2；工具正确返回 1。已只修正试用脚本的预期并复核，保留 [初次记录](forward/validation/18-release-gate.json) 和 [复核记录](forward/validation/19-release-gate-confirmed.json)。不将这次执行算为首轮无误。

## 独立试用的专业产出核读

[DIRECTOR-REVIEW.md](forward/DIRECTOR-REVIEW.md)给出实际可以评审的内容：街区生活的项目定位；轮廓、大小形、色彩职能、材质与细节密度；组件可读性与真实文字；跨岗位接口；样板先后顺序和依赖；需要主美决定的具体取舍。输出含 8 个家族、22 条候选规则、5 项样板计划，以及五份派生手册和团队 ZIP。

它没有把图片阅读分辨率当成交付尺寸，没有自造主美批准，也没有把未制作的样板标为完成。图片提供方向依据，项目决策仍有状态和来源。此结果说明当前 Skill 可以驱动宿主 Agent 建立具体交接成果，而不是只抛给主美一套空表。

这是一次 Agent 试用与人工核读，不能替代真实主美、设计师和外包的持续试用，也不能单独证明所有使用者都会获得同样结果。

## 根据试用补齐的交接规则

运行层的组合组件绑定类别、家族和实体；子组件的状态、等级、姿态不会自动继承父任务变量。因此先建立有各自变化的子资产任务，再在组合工作目录记录实际文件、状态、版本与检查，最后看真实组合。母 Skill v0.5.1 在[成员指南](../../references/member-workflow.md)明确了这一步，由 Agent 管理记录，不要求设计师手工工程化。此次说明补充没有改变被测核心脚本。

## 能力边界与下一批次的效果验收

本轮执行了规范整理、文档派生、接包、任务编译、版本和批次检查。新图生成、PS/Figma 编辑、引擎或真实渠道集成、真实艺术批准与真人团队实验均没有在本轮执行；原有原创图片用于方向和演示。所有相应待检项保持未知。

在真实生产批次中，主美先确认共同材料、规则及代表样板；成员通过 Skill 调用所在环境可用的制作工具，交付单件、编辑源和组合证据。按同样任务、输入和模型条件比较自由描述与 Skill 两种流程，记录身份/品牌错误、风格错误、首过率、返工轮次及总用时，保留缺失项和失败分母。工程检查已经跑通，品质与效率提升以这些实际结果判断。
